# ゆかりちゃん Live2D モデル制作リクエスト仕様

ゆかナビのマスコット「ゆかり」ちゃんを Live2D 化するための制作仕様。
外注時はこの文書 + 「参考素材一式」(§9) をそのまま渡す。自作時は作業チェックリストとして使う。

## 1. 用途 (どう表示されるか)

- カラオケリクエストアプリ「ゆかナビ」のホーム画面マスコット。画面下部に**全身立ち絵**で常駐
- 表示枠は縦長 (幅 740 x 高さ 1110 相当、2:3)。アプリ側が RenderTexture (1024x1536) に描画する
- 常時: 呼吸 + ゆるい揺れ + まばたき。タップ: 表情が切り替わり、セリフ吹き出しが出る
- 動きのテイストは「静かに生きている」寄り。VTuber 的な大きな首振り・体の回転は不要
  (現行の静止画版は ±0.5° の傾きと 1% 未満の伸縮で呼吸を表現している。この上位互換が目標)

## 2. 納品物

| 種別 | 内容 |
|---|---|
| 編集元データ | `.cmo3` (Cubism Editor プロジェクト)、使用した PSD (再構成した場合はそれも) |
| 組み込み用書き出し一式 | `.moc3` / `.model3.json` / テクスチャアトラス PNG / `.physics3.json` / `.cdi3.json` |
| モーション | `.motion3.json` (§6)。表情は `.exp3.json` (§5) |
| 動作サンプル | Cubism Viewer で開ける状態、または録画 (検収の一次確認用) |

- **Cubism 5 系 Editor で制作・書き出し**すること (アプリ側 SDK は Cubism 5 SDK for Unity R5 / URP)
- `.cmo3` を含む全データの改変可能な形での納品必須 (将来の衣装差分・表情追加のため)
- `.model3.json` から参照するパスはすべてモデルフォルダ内の相対パスにし、
  Cubism Viewer へ `.model3.json` を単体でドロップして不足ファイルなく開ける状態にする
- 組み込み用ファイル名・フォルダ名は Android / Windows / iOS 共通で扱いやすい
  **半角英数字・小文字 snake_case** に統一する

組み込み時の推奨構成 (名前を変更する場合は事前にアプリ側と合意する):

```text
yukari/
├── yukari.model3.json
├── yukari.moc3
├── yukari.physics3.json
├── yukari.cdi3.json
├── textures/
│   └── texture_00.png
├── motions/
│   ├── idle.motion3.json
│   └── tap_body.motion3.json
└── expressions/
    ├── smile.exp3.json
    ├── wink.exp3.json
    └── surprised.exp3.json
```

## 3. ベース素材と制約

- パーツ分解済み PSD: `yukari_parts_source.psd` (1024x1536 / 24 レイヤー、構成は `manifest.json`)
  - 目は左右それぞれ 白目 / 虹彩 / まぶた に分解済み、口は開/閉 2 枚、眉は左右独立
  - 腕・マイク・タブレットは独立レイヤーだが、腕側にも重なりを少し残してある
    (初期表示で穴が出にくくしてある。リギング側でマスク調整しやすいはず)
- **注意: 1 枚絵からの分解のため、重なりの裏側は近似**。§4 フェーズ 1〜2 の可動域なら
  そのまま使える想定だが、**破綻する箇所の描き足し・レイヤー再分解は制作側の裁量で行ってよい**
  (むしろ推奨。その場合は再構成後の PSD も納品に含めること)
- 完成時の見た目 (色味・プロポーション) は `../yukari_mascot_transparent.png` が正。
  勝手なリファイン (目のサイズ変更等) はしない

### 3.1 フェーズ 0: 原画クリーンアップ (リギング前に必須)

現状の `yukari_parts_recomposed_preview.png` には、顔の境界線・肩・両肘付近に
継ぎ目や白抜けが見える。リギング開始前に、パラメータがすべてデフォルト値の状態で
元の `yukari_mascot_transparent.png` と同じ見た目になるよう修正すること。

- 顔・前髪・白目・口内・首・肩・袖・腕・髪の根元など、動いたときに露出する裏側を描き足す
- 腕とマイク / タブレットに残した重複は、マスクまたは再分解で二重線が出ないよう整理する
- 100% 表示と市松模様背景の両方で、隙間・白縁・色境界・二重線がないことを確認する
- クリーンアップ後の PSD と、全レイヤーを重ねた確認用 PNG を納品する

## 4. スコープ (フェーズ分け)

**今回の発注はフェーズ 1 + 2。**フェーズ 3 は将来の追加発注 (見積りだけ歓迎)。

| フェーズ | 内容 | 素材描き足し |
|---|---|---|
| **0. 原画整理 (必須)** | デフォルト姿勢の継ぎ目修正、隠れ部分の描き足し、レイヤー再整理 (§3.1) | 必要 |
| **1. 最小 (必須)** | 呼吸、まばたき、顔・体の微揺れ (アイドル)、髪とリボンの物理揺れ | 原則不要 |
| **2. 標準 (必須)** | 表情 3 種 (§5)、視線 (目玉 XY)、口の開閉、タップリアクションモーション | 軽微 |
| 3. 拡張 (将来) | 大きめの首振り (±30°)、予約完了ポーズ、案内ポーズ、リップシンク運用 | 必要 |

## 5. パラメータ・表情

**Cubism 標準パラメータ ID を必ず使う**こと (SDK の自動まばたき・視線追従・
リップシンク機能が標準 ID 前提のため。独自 ID はアプリ側改修が必要になる)。

フェーズ 1+2 で必要なパラメータ:

| パラメータ | ID | 可動域の目安 |
|---|---|---|
| まばたき 左右 | `ParamEyeLOpen` / `ParamEyeROpen` | 1 (開) 〜 0 (閉)。閉じ目はまぶたレイヤーを活かす |
| 笑顔目 左右 | `ParamEyeLSmile` / `ParamEyeRSmile` | 表情用 |
| 目玉 XY | `ParamEyeBallX` / `ParamEyeBallY` | 小さめで自然に |
| 眉 上下・形 | `ParamBrowLY` / `ParamBrowRY` / `ParamBrowLForm` / `ParamBrowRForm` | 表情用 |
| 口 開閉・形 | `ParamMouthOpenY` / `ParamMouthForm` | 開閉 0〜1 (将来のリップシンク用に必須)、形 -1〜1 |
| 顔の向き | `ParamAngleX` / `ParamAngleY` / `ParamAngleZ` | **±10° 程度で OK** (フェーズ 3 で拡張) |
| 体の傾き | `ParamBodyAngleX` / `ParamBodyAngleZ` | ±5° 程度 |
| 呼吸 | `ParamBreath` | 0〜1 |

`.model3.json` の `Groups` には次を必ず設定する。SDK はこのグループ情報から
自動まばたき・リップシンク対象を解決するため、パラメータ ID だけ合っていても
グループが無い状態は不可。

```json
[
  {
    "Target": "Parameter",
    "Name": "EyeBlink",
    "Ids": ["ParamEyeLOpen", "ParamEyeROpen"]
  },
  {
    "Target": "Parameter",
    "Name": "LipSync",
    "Ids": ["ParamMouthOpenY"]
  }
]
```

表情 (`.exp3.json`、既存の表情差分 PNG が見た目の正):

| 表情 | 対応する既存素材 | 内容 |
|---|---|---|
| `exp_smile` | `yukari_expr_smile.png` | にっこり (笑顔目 + 口角上げ) |
| `exp_wink` | `yukari_expr_wink.png` | ウィンク (片目閉じ + 笑顔) |
| `exp_surprised` | `yukari_expr_surprised.png` | 驚き (目見開き + 口開け + 眉上げ) |

## 6. モーション

| モーション | 長さ | 内容 |
|---|---|---|
| `Idle` | 15〜20 秒ループ | 呼吸 + ごく僅かな体の揺れ・重心移動。**シームレスにループ**すること |
| `TapBody` | 1〜2 秒 | タップされたときの「ぴょこん」と弾む/喜ぶリアクション。終了後 Idle に自然に戻る |

- `.model3.json` のモーショングループ名は **`Idle` / `TapBody`** に固定する
- `Idle` はループ有効、フェードイン / アウトは各 0.5〜1.0 秒を目安にする
- `TapBody` はループ無効、フェードイン 0.1〜0.2 秒、フェードアウト 0.3〜0.5 秒を目安にし、
  終端ではデフォルト姿勢へ戻して次の Idle と自然につなぐ
- **まばたきはモーションに焼き込まない** (`ParamEyeL/ROpen` にキーを打たない)。
  アプリ側が SDK の自動まばたき (`CubismEyeBlinkController`) で制御する
- **呼吸もモーションに焼き込まない** (`ParamBreath` にキーを打たない)。
  アプリ側が SDK の HarmonicMotion で `ParamBreath` を一定周期で揺らすため、
  モーション側にも入っていると同じパラメータの取り合いになる。
  **ただしパラメータ自体 (`ParamBreath` と、それに紐づく胸・肩などの変形) は必須**
- **`ParamBreath` の変形量は「引きで見て呼吸が分かる」大きさにする**。
  ホーム画面ではキャラが小さく表示されるため、試作版の変形量では拡大しないと
  呼吸に気づけなかった。アプリは `ParamBreath` を 0〜1 のフルレンジで動かすので、
  見た目の大きさはモデル側の変形量だけで決まる
- 物理演算 (髪・リボン) はモーションと独立して揺れるので、モーション側は体の動きだけでよい
- 表情のパラメータをモーションへ焼き込まず、`.exp3.json` と競合しないようにする
- `TapBody` 中もモデル全体の描画範囲が大きく変わらず、RenderTexture の端で見切れないこと

## 7. 物理演算 (`.physics3.json`)

- 対象: 前髪 / サイド髪 左右 / 後髪 / ヘッドセットのリボン
- 揺れは控えめに (アイドルの微揺れで髪がふわっと反応する程度)。過剰なバネ感は不要

## 8. 技術制約 (モバイル動作のため)

- テクスチャアトラス: **2048x2048 を 1 枚**に収める
- アートメッシュ数: 必要最小限 (目安 100〜250。SDK サンプル Mao が 262 で問題なく動いている)
- クリッピングマスクは目・口など標準的な箇所のみ。反転マスクや多段マスクの多用は避ける
- キャンバス: 全身が収まり、動いても見切れないよう周囲に 5〜10% の余白。
  モデル原点はキャンバス中央系のままでよい (表示位置・サイズはアプリが自動フィットする)
- **デフォルト状態で使わないアートメッシュは、不透明度を 0 にしておく**こと。
  アプリは「不透明度が 0 より大きいアートメッシュ」の範囲からモデルの表示サイズを
  自動計算するため、非表示のはずのパーツが不透明のまま画面外や広い位置にあると、
  モデルが実際より小さく表示される (SDK サンプルの Mao で、未使用パーツを含めると
  範囲が見た目の 2 倍以上になる事象を確認済み)。
  同様に、**表示されない補助メッシュを本体から大きく離れた位置に置かない**こと
- テクスチャ書き出し時は「色漏れ防止処理」を有効にし、透明境界の白縁・黒縁がないこと
- `.model3.json` の `FileReferences` にテクスチャ・物理・表情・モーションをすべて登録し、
  絶対パスや制作端末固有のパスを残さないこと
- 動作確認環境: Cubism 5 SDK for Unity R5 (URP / Unity 6)。アプリ側は Color Space が
  **Linear** のため Editor と色味が僅かに変わる可能性がある。最終検収は Unity 取り込みで行う

## 10. 検収基準

1. デフォルト姿勢を透過 PNG で書き出したとき、元の `yukari_mascot_transparent.png` と
   見た目が一致し、継ぎ目・白抜け・二重線がない
2. Cubism Viewer で `.model3.json` が不足参照なく開き、Idle ループが自然につながり、
   髪・リボンが揺れる
3. Unity (Cubism 5 SDK R5 / URP) にインポートして表示・Idle・自動まばたき・表情 3 種・
   TapBody が動作する (アプリへの組み込み確認はこちらで行う)
4. EyeBlink / LipSync のグループ、Idle / TapBody のモーショングループ、表情 3 種が
   `.model3.json` に正しく登録されている
5. 表情解除・TapBody 終了時にパラメータが自然にデフォルトへ戻り、次の Idle と競合しない
6. 静止状態の色味・プロポーションが既存立ち絵と一致し、Linear Color Space でも破綻しない
7. `.cmo3` を開いて編集できる (レイヤー・デフォーマに識別可能な名前が付いている)

## 11. ライセンス・契約まわりのメモ (発注側の控え)

- 納品データ (`.cmo3` 含む) は改変・再書き出しを含む利用権を確保すること
- 制作側の Cubism Editor は **PRO 版推奨** (FREE 版はアートメッシュ数・パラメータ数・
  デフォーマ数・テクスチャサイズに制限があり、パラメータ反転等の効率化機能も使えない。
  最新の制限は[公式の機能比較](https://www.live2d.com/cubism/download/editor/)を参照)
- アプリ側 (ゆかナビ) は外部スキンからモデルを追加できる設計のため、
  Live2D の「拡張性アプリケーション」に該当する可能性がある。小規模事業者の免除を前提にせず、
  公開前に Live2D 社へ利用形態と出版許諾契約の要否を確認する

## 12. 制作・検収の区切り

手戻りを抑えるため、次の順で中間確認する。

1. **原画確認**: クリーンアップ済みPSDとデフォルト姿勢PNG
2. **モデル確認**: 顔XY・目・口・体・呼吸まで。物理とモーションは未実装でよい
3. **物理確認**: 髪・リボンの揺れ
4. **表情確認**: smile / wink / surprised
5. **モーション確認**: Idle / TapBody
6. **最終確認**: Viewer一式と編集元を受領し、Unityへ組み込んで検収

各区切りで短い録画または Viewer 用データを共有し、次工程へ進む前に承認を取る。
